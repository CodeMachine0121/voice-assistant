### Notes on recheck and disagreement

- **AC-9 / AC-10 (🟠, Jev: shallow).** The only test is at controller level
  (`controller.rs:174` / `:223`). It asserts `StopAndProcess`, but not that text is written.
  No engine test drives a stop at exactly 500 ms or a Tick-driven 5-minute stop through to an
  insertion (the engine rig uses 550 ms, and no test covers the Tick path end to end). Code path
  checked: `engine.rs:104-144` → pipeline. It produces the oracle.
- **BR-5 (shadow 🔴, Jev ✅, escalated).** The PRD says "Chinese results are written in Traditional
  characters in every action". `pipeline.rs:101-104` applies `to_traditional` to the result
  only for Dictate. An Edit-selection result is written as the model returns it, and
  `pipeline.rs:474-481` (`edit_writes_the_result_as_given_so_an_instruction_may_ask_for_simplified`)
  asserts that Simplified output is written. ARCH §3 chose this exception on purpose. The PRD
  does not have it. This is a spec/design conflict.
- **NFR-2 (shadow 🔴, Jev ✅, escalated).** "What the user had copied is always restored" breaks
  in three cases:
  - Without Accessibility permission, `paste.rs:66-69` puts the result on the clipboard and
    returns. The user's earlier copy is lost, and `paste.rs:476` asserts this behaviour.
  - When the paste fails, `paste.rs:73-75` leaves the text on the clipboard.
  - When the clipboard changes during the paste, it is left alone (`paste.rs:77-80`). This
    exception is reasonable.

  Separately, "only sent to the local AI app on this Mac" is not enforced. `assistant_url` is
  any address the user types, and it also serves as the speech server (`real.rs:113-117`).
- **AC-29 (shadow ❔, Jev ✅, escalated).** The core path conforms (`Ok(None)` → `NoSelection`,
  recorder never started). The adapter is the risk. When Accessibility reports an *empty*
  selection, `selection.rs:41-44` still posts ⌘C to the front app. Editors like VS Code,
  Sublime and JetBrains copy the whole current line when nothing is selected, so Edit starts
  with that line as the "selection". The persona explicitly uses a code editor.
- **AC-13, AC-21, AC-24, AC-25, AC-26, BR-4 (shadow ❔, Jev ✅).** These depend on the LLM (see the
  header). The prompt structure is sound: tagged data, neutralised tags, and few-shots for
  injection, shorten and translate. `prompt.rs:92` embeds the AC-21 example word for word, so
  that prompt is tuned to the acceptance example.
- **AC-15, AC-20 (🟡, Jev: no-test), AC-18, AC-19 (❔).** Same LLM ceiling. No test pins the
  scenario's own example ("what time is it", English fillers → "I think we're done.").
- **Recheck routes** (AC-6, AC-14, AC-22, AC-31, AC-33, AC-42, AC-44, BR-1, BR-2, BR-6, BR-7, BR-9,
